# Nexus v0.2.0

**Released:** 2026-10-23 · **Tag:** `v0.2.0`

## What is Nexus

Nexus is a local-first, open-source companion for connecting your Android phone
and desktop. It discovers your devices on the local network, pairs them once by
comparing a short code on both screens, and then keeps a direct TLS 1.3
connection between them so the clipboard stays in sync. No account, no server,
no cloud.

## What's new

### Guided device setup

- A short **Set up a device** walkthrough is now available on the phone
  (**Devices → Set up**, and from the home screen) and on the desktop
  (**Devices → Set up your phone**).
- Each step explains what to do: same Wi-Fi, open a 60-second pairing window,
  then pair from the other device and compare the 6-digit code.
- The guide reuses the existing pairing flow — it does not bypass or replace
  certificate pinning, and it can be opened again at any time.

### Start on boot

- Nexus can restore its local link after the phone or computer restarts.
- **Phone:** `Start on boot` in **Settings** (default on). The background
  service starts after the system completes its own boot work; notification
  access and clipboard behaviour are unchanged.
- **Computer:** start with Windows is enabled by default on first launch
  (Settings → Startup). The desktop app opens normally, so the window is
  visible as before.
- Both toggles persist across restarts.

### Notification mirroring (phone → computer)

- Opt in on the phone under **Settings → Mirror notifications**; Android will
  ask for notification-listener access. It is off by default.
- Notifications posted on the phone appear as native Windows toasts and in the
  desktop app's **Notifications** page (in memory only, newest first, up to 50).
- **Hide notification text** forwards only the app name and title, never the
  message body.
- The desktop has its own **Settings → Phone notifications** toggle and a
  **Clear** action. Turning mirroring off on either side stops it immediately.
- Privacy: content travels only over the existing paired, encrypted connection.
  It is never uploaded, stored on disk, or written to logs; activity entries
  name only the app. The phone never mirrors its own notifications, ongoing
  items, group summaries, or duplicate posts.

### Under the hood

- The Android runtime now owns one discovery/session controller for both the
  activity and the background service, with separate network and clipboard
  lifecycles.
- Notification forwarding runs on a background thread, so it cannot block the
  Android main thread.
- Both apps advertise the `notifications` feature in `system.hello`; the phone
  only sends to a computer that advertised support. The wire format is
  documented in [`protocol/notifications.md`](../protocol/notifications.md).
- New unit coverage for notification mapping/filtering, plus the existing
  protocol, pairing, trust and reconnect suites.

## Downloads

- **Windows** — `Nexus_0.2.0_x64-setup.exe` (NSIS installer) or
  `Nexus_0.2.0_x64_en-US.msi`.
- **Android** — `app-release.apk`.

Upgrading in place keeps your paired devices: the Android APK and the Windows
installers use the same signing keys as v0.1.0.

## Getting started

1. Install Nexus on both devices and put them on the same Wi-Fi network.
2. Open **Devices → Set up** on the phone (or **Set up your phone** on the
   desktop) and follow the steps.
3. Confirm the same 6-digit code on both screens.
4. Optional: enable **Mirror notifications** on the phone and grant access.

## Known limitations

- **Android clipboard is foreground-only.** Just like v0.1.0, a copy made on the
  phone is only picked up while Nexus is open and focused. Starting on boot
  keeps the link ready but does not change Android's clipboard rule.
- **Notification mirroring is opt-in and one-way.** You cannot reply, dismiss or
  act on a notification from the computer, and the list is not persisted.
- **Start on boot is best-effort.** Some Android vendors delay boot receivers,
  and aggressive battery optimisation can stop the background link. Use the
  Settings toggles if you prefer manual starts.
- **Plain text only** — no images, files or rich text.
- **One active connection at a time** per device.
- **Platform support** — Windows and Linux (X11) are primary; Wayland and macOS
  are best-effort and untested. v0.2 installers are published for Windows.

## Not included

File transfer between paired devices, media control, and notification actions
from the computer remain on the roadmap.

## Security and privacy notes

- Devices generate their own certificate and private key locally; private keys
  are never transmitted.
- Connections are only accepted between paired, pinned devices.
- Mirroring requires explicit notification-listener access on the phone, and the
  phone applies all filtering before anything is sent.
- No analytics or telemetry. Clipboard and notification content are never
  written to logs or stored on disk.

## Notes for maintainers

- The Windows installers and the release APK are **signed with a throwaway key**
  used to verify the release pipeline. Replace it with the project's real
  release keys before publishing artifacts.
